# 보안 규칙 (Security) — 예외 없는 절대 규칙

## MUST

- 비밀(개인 키)은 `~/.ssh` 아래 0600 파일로만 존재시키고, JSON 저장소에는
  키 평문을 넣지 않는다.
- 사용자 입력으로 파일명을 만들 때 새니타이즈한다(`keyFileName` —
  crates/sshub-core/src/key_files.rs, 영숫자·`-`·`_`만 허용, 나머지 `_`). 경로
  traversal(`../`) 차단을 테스트로 고정한다.
- 내보내기(`backup::export_data`)는 기본적으로 비밀을 제거한다. 개인 키를 포함해
  내보낼 때는 AES-256-GCM(scrypt) passphrase 암호화를 적용한다
  (`crates/sshub-core/src/crypto.rs`).
- 비밀번호는 연결 시 터미널에서 직접 입력하게 한다.
- 네이티브 앱이라 renderer 신뢰 경계가 없다 — 대신 사용자 입력이 파일
  경로가 되는 지점(키 파일명·별칭)에서 새니타이즈한다.
- 개인 키 파일 권한을 0600으로 설정하고, 키 rename 시 개인 키 파일도 함께
  이동해 접속 경로 정합성을 유지한다.

## MUST NOT

- 개인 키 평문을 JSON 저장소·로그·내보내기 파일에 기록하지 않는다.
- 비밀번호를 저장하지 않는다.
- 사용자 입력을 검증 없이 fs/spawn에 넘기지 않는다.
- 테스트에서 실제 `~/.ssh`를 건드리지 않는다.

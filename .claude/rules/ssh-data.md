# SSH 데이터 규칙 — 사용자 파일을 망가뜨리지 않기

`~/.ssh/config`와 `~/.ssh`의 키는 **사용자 소유**다. 앱은 손님이다.

## MUST

- config 편집은 `ssh_config::document`로 외과적으로 한다. 라운드트립 바이트
  동일이 불변식이고, 건드리는 줄만 교체한다.
- 값이 없다고 사용자 줄을 지우지 않는다. (비밀번호 인증 서버 때문에 사용자의
  `IdentityFile` 3줄을 지운 사고가 있었다.)
- 같은 키가 여러 줄이면 첫 줄만 갱신하고 나머지는 둔다 — `IdentityFile`
  여러 줄은 OpenSSH가 순서대로 시도하는 정상 설정이다.
- 새 블록은 첫 와일드카드 블록 앞에 넣는다.
- 쓰기 = 타임스탬프 백업 → 원자적 쓰기 → 권한 보존. config를 못 읽으면 모든
  쓰기를 막는다(빈 문서로 덮어쓰는 사고 방지).
- `~/.ssh`의 파일은 마이그레이션에서 절대 덮어쓰거나 지우지 않는다.
- 키 삭제는 실제 파일을 지우는 일이다 — 확인 대화상자와 참조 서버 수를 보여준다.

## MUST NOT

- 테스트에서 실제 `~/.ssh`·`~/Library/Application Support/`를 건드리지 않는다.
- 전체 파일 렌더러를 다시 만들지 않는다.
